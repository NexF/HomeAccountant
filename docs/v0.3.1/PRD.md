# v0.3.1 — 注册邀请码验证

## 1. 版本概述

### 1.1 版本目标

为注册流程增加邀请码验证，实现注册准入控制，仅持有有效邀请码的用户才能注册。

### 1.2 现状分析

- 当前注册流程：用户输入邮箱+密码 → 直接创建账户 → 登录态
- 任何人都可以注册，无任何准入限制

### 1.3 设计决策

| 决策 | 选择 | 原因 |
|------|------|------|
| 邀请码格式 | 固定 6 位字母+数字 | 简短易记，便于口头或消息传递 |
| 邀请码来源 | 环境变量配置 | 最简实现，无需数据库存储，适合小团队/个人使用 |
| 验证时机 | 注册时服务端校验 | 防止绕过前端直接调 API |
| 大小写 | 不区分大小写 | 减少输入错误 |

### 1.4 不包含的内容

- 邀请码动态生成/管理后台
- 邀请码使用次数限制
- 邮箱验证（计划后续版本）
- 忘记密码 / 密码重置

---

## 2. 用户流程

```
用户输入邮箱 + 密码 + 昵称 + 邀请码
                ↓
          点击「注册」
                ↓
后端校验邀请码是否正确（不区分大小写）
                ↓
         校验通过 → 创建账户 → 返回 JWT
         校验失败 → 返回 403 "邀请码无效"
```

### 异常场景

| 场景 | 处理 |
|------|------|
| 邀请码为空 | 返回 422 "请输入邀请码" |
| 邀请码错误 | 返回 403 "邀请码无效" |
| 邮箱已注册 | 返回 409 "该邮箱已注册" |
| 未配置邀请码（环境变量为空） | 跳过验证，允许自由注册（开发模式） |

## 3. API 设计

### 3.1 `POST /auth/register`（改造）

新增必填字段 `invite_code`。

**请求体：**
```json
{
  "email": "user@example.com",
  "password": "123456",
  "nickname": "小明",
  "invite_code": "ABC123"
}
```

**成功响应（200）：** 不变，返回 JWT。

**失败响应新增：**
- `403` — 邀请码无效
- `422` — 邀请码为空

### 3.2 配置项新增

`config.py` / `.env`：

| 配置项 | 说明 | 默认值 |
|--------|------|--------|
| `INVITE_CODE` | 注册邀请码（6 位字母数字） | `""`（空=不校验） |

---

## 4. 前端改造

### 4.1 注册页面 `register.tsx`

在密码确认框下方、注册按钮上方新增**邀请码输入框**：

- 标签：「邀请码」
- placeholder：`"请输入6位邀请码"`
- 键盘类型：default
- 自动大写：关闭
- 最大长度：6

### 4.2 authService.ts

修改 `RegisterParams`：
```typescript
interface RegisterParams {
  email: string;
  password: string;
  nickname?: string;
  invite_code: string;  // 新增
}
```

## 6. 验收标准

| # | 场景 | 预期结果 |
|---|------|----------|
| 1 | 输入正确邀请码注册 | 注册成功，自动登录 |
| 2 | 输入错误邀请码 | 提示"邀请码无效" |
| 3 | 不输入邀请码 | 提示"请输入邀请码" |
| 4 | 邀请码大小写不同 | 仍然通过（不区分大小写） |
| 5 | 环境变量未配置邀请码 | 注册不校验邀请码（开发模式） |
| 6 | 已有注册测试仍通过 | 测试 fixture 中传入正确邀请码 |

## 7. 部署配置

在 `server/docker/.env` 或 `docker-compose.yml` 中添加：

```env
INVITE_CODE=ABC123
```

更换邀请码只需修改环境变量并重启容器，无需改代码。
