# v0.4.0 — 管理后台

## 1. 背景

项目当前没有管理后台，无法查看系统整体情况和管理用户。需要一个轻量的管理页面来查看统计数据、管理用户。

## 2. 目标

提供一个密码保护的管理后台，支持系统概览、用户管理、账本概览。

## 3. 鉴权方式

**不引入用户角色系统**，采用独立的管理密码方案：

- 通过环境变量 `ADMIN_PASSWORD` 配置管理密码
- 前端进入管理后台时输入密码验证
- 验证通过后后端返回一个短期 admin token（有效期 2 小时）
- 后续所有 `/admin/*` 接口通过 `X-Admin-Token` 请求头鉴权
- 未配置 `ADMIN_PASSWORD` 时管理后台不可用

```
┌──────────────────────┐
│      管理后台         │
│                      │
│  管理密码: [••••••]   │
│                      │
│      [进入后台]       │
└──────────────────────┘
```

- admin token 使用 JWT 签发，payload 中标记 `type: "admin"`
- 与用户登录 token 完全独立，不依赖任何用户身份

## 4. 功能清单

### 4.1 系统概览仪表板

管理后台首页展示系统核心指标：

| 指标 | 说明 |
|------|------|
| 注册用户总数 | 含活跃/封禁分类 |
| 账本总数 | 含个人/家庭分类 |
| 分录总数 | 所有账本的记账笔数 |
| 今日新增用户 | 当天注册数 |
| 今日新增分录 | 当天记账数 |
| 活跃用户数 | 近 7 天有登录或记账操作的用户数 |

### 4.2 用户管理

#### 用户列表

| 字段 | 说明 |
|------|------|
| 头像 | avatar_url 或默认头像 |
| 昵称 | nickname |
| 邮箱 | email |
| 状态 | 正常 / 已封禁 |
| 账本数 | 该用户拥有的账本数量 |
| 注册时间 | created_at |
| 最后活跃 | last_active_at |

- 支持按邮箱/昵称搜索
- 支持按状态筛选（全部/正常/已封禁）
- 支持分页（每页 20 条）

#### 用户详情 / 编辑

管理员可修改用户的以下字段：

| 字段 | 可编辑 | 说明 |
|------|--------|------|
| nickname | ✅ | 修改昵称 |
| email | ❌ | 仅查看，不可改 |
| 状态 | ✅ | 封禁 / 解封 |

#### 封禁用户

- 封禁后该用户无法登录（登录接口返回 403）
- 封禁后已有的 Token 立即失效（通过 `is_active` 字段在 `get_current_user` 中校验）
- 封禁/解封操作需要确认弹窗

### 4.3 账本概览（只读）

查看所有账本列表，但**不能进入或修改**账本数据（隐私原则）：

| 字段 | 说明 |
|------|------|
| 账本名 | name |
| 类型 | 个人 / 家庭 |
| 拥有者 | owner 的昵称和邮箱 |
| 成员数 | BookMember 数量 |
| 分录数 | JournalEntry 数量 |
| 创建时间 | created_at |

- 支持搜索、分页
- 只读，不可编辑或删除

## 5. 页面设计

### 5.1 入口

- **无显式入口**，不在任何页面中展示管理后台链接
- 用户需在浏览器地址栏手动输入 `/admin` 进入
- 首次进入显示密码验证页，验证通过后进入管理后台
- `ADMIN_PASSWORD` 未配置时访问 `/admin` 显示"管理后台未启用"

## 6. API 设计

所有 `/admin/*` 接口通过 `X-Admin-Token` 请求头鉴权。

### 6.0 管理密码验证

```
POST /admin/login
```

请求体：
```json
{
  "password": "管理密码"
}
```

成功响应：
```json
{
  "admin_token": "eyJhbGciOiJIUzI1NiIs...",
  "expires_in": 7200
}
```

失败响应：`403 Forbidden`

## 7. 数据模型变更

### User 表新增字段

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `is_active` | `Boolean` | `True` | 是否启用（封禁=False） |
| `last_active_at` | `DateTime` | `None` | 最后活跃时间 |

不新增 `role` 字段，管理员身份与用户模型完全解耦。

迁移方式：沿用项目现有的 `ALTER TABLE` + `PRAGMA table_info` 模式在 `init_db()` 中添加。

### config.py 新增

| 配置项 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| `ADMIN_PASSWORD` | `str` | `""` | 管理密码，为空则管理后台不可用 |

## 8. 鉴权

- `POST /admin/login`：验证管理密码，返回 admin JWT token（payload: `{"type": "admin", "exp": ...}`）
- 其他 `/admin/*` 接口：新增依赖 `require_admin_token`，从 `X-Admin-Token` 头提取并验证 JWT
- admin token 有效期 2 小时
- 与用户认证体系完全独立

## 9. 前端路由

```
client/app/
├── admin/
│   ├── _layout.tsx      # 管理后台布局（含 admin token 守卫 + 导航）
│   ├── index.tsx        # 概览仪表板
│   ├── login.tsx        # 管理密码输入页
│   ├── users.tsx        # 用户列表
│   ├── user/[id].tsx    # 用户详情/编辑
│   └── books.tsx        # 账本列表
```

前端存储 admin token 到内存（不持久化到 AsyncStorage，关闭页面即失效）。

## 10. 安全约束

- 管理后台不能查看/修改用户密码
- 管理后台不能进入其他用户的账本数据（只读元信息）
- 封禁用户后其现有 Token 在下次请求时失效（`get_current_user` 校验 `is_active`）
- admin token 短期有效（2h），不持久化
- `ADMIN_PASSWORD` 为空时所有 admin 接口返回 404（隐藏管理后台存在）

## 11. 非目标（本版本不做）

- 用户角色系统（admin/user）
- 操作日志/审计记录
- 批量操作
- 系统配置管理（如修改邀请码）
- 数据导出
- 用户删除（仅支持封禁）
