# v0.4.3 — 资产负债表内联编辑（快速对账）

> **版本：v0.4.3**
> **创建日期：2026-02-28**
> **基于版本：v0.4.2**
> **状态：规划中**
> **本版本变更：在资产负债表中为叶子科目增加内联余额编辑能力，缩短对账路径，一站式完成余额核实与调节**

---

## 1. 背景

### 1.1 对账入口隐藏太深

当前系统的对账功能有 3 个入口，但每个都需要较长的导航路径：

| 入口 | 路径 | 步骤数 |
|------|------|--------|
| 首页待处理角标 | 首页 → 点击角标 → `/sync/reconcile` | 2步（且仅在有 pending 时显示） |
| 科目详情页 | 科目列表 → 点击科目 → 滚动到对账区 → 输入余额 | 3步 |
| 桌面端科目面板 | 设置 → 科目管理 → 展开科目 → 输入余额 | 3步 |

用户最常想做的操作是：**看到资产负债表上的某个科目余额不对，想立刻修正**。但当前必须离开报表页面，去科目详情页找到对账入口，操作链路长、上下文丢失。

### 1.2 报表与对账场景天然关联

资产负债表本身就是一张"余额核查清单"——每一行科目都显示着当前余额。用户核对真实资产时（如登录银行APP查余额），最直观的操作是：**直接在报表行上点击，输入真实余额，系统自动调平**。

这与传统企业会计的"对账单勾兑"流程一致：看到差异 → 直接标注 → 生成调节。

### 1.3 现有对账能力完善

后端 `reconciliation_service.create_snapshot()` 已完整实现：
- 计算差异（外部余额 - 账本余额）
- 差异为 0 → 标记 balanced
- 差异不为 0 → 自动生成调节分录（暂挂到"待分类费用/收入"）
- 后续由用户在 `/sync/reconcile` 确认分类

**本版本不改动后端对账逻辑，只在前端增加一个更短的入口。**

## 2. 目标

| 能力 | 说明 |
|------|------|
| 内联编辑入口 | 资产负债表的叶子科目行支持点击余额，弹出编辑输入框 |
| 快速对账 | 输入真实余额后，直接调用 `submitSnapshot` 完成对账 |
| 即时反馈 | 对账成功后就地刷新余额，显示差异和对账状态 |
| 待处理引导 | 差异不为 0 时，提示用户前往确认调节分录分类 |
| 不影响父科目 | 仅叶子科目（无子科目）可编辑，父科目余额由子科目汇总 |

### 设计原则

- **最短路径**：从"看到问题"到"解决问题"不超过 2 步（点击 → 输入 → 提交）
- **复用现有后端**：完全复用 `reconciliation_service` 和 `sync` API，不新增后端接口
- **非破坏性**：编辑操作通过对账机制间接修改余额（生成调节分录），不直接修改科目余额
- **渐进增强**：不改变现有对账流程，只增加一个新入口

## 3. 交互设计

### 3.0 全局隐藏科目代码

所有面向用户的页面中不再展示科目代码（如 `1001`、`1001-02`），仅显示科目名称。原因：
- 科目代码是内部编码，对普通用户无意义，增加视觉噪音
- 树形缩进 + 科目名称已足够表达层级关系

**涉及页面：**

| 页面 | 隐藏位置 |
|------|---------|
| 资产负债表 | 科目行的编码列 |
| 科目管理 — 列表（桌面端 + 移动端） | 科目行的编码标签 |
| 科目管理 — 详情（桌面端 + 移动端） | 信息卡"编码"行 |
| 科目管理 — 子科目列表 | 子科目行的编码标签 |
| 科目管理 — 新增子科目弹窗 | 父科目标签中的编码后缀 |

> 注：科目代码仍保留在数据模型和后端 API 中，仅前端不展示。

### 3.1 资产负债表 — 正常状态

叶子科目行的余额区域增加可点击视觉提示（hover 时变色、显示编辑图标）：

```
┌─────────────────────────────────────────────────┐
│  资产                                            │
├─────────────────────────────────────────────────┤
│  ▼ 货币资金                             ¥233.00  │  ← 父科目，不可编辑
│      现金                                ¥0.00 ✎ │  ← 叶子科目，可编辑
│      存款                              ¥233.00 ✎ │  ← 叶子科目，可编辑
│  ▼ 现金等价物                             ¥0.00  │
│      货币基金                             ¥0.00 ✎ │
│      短期国债                             ¥0.00 ✎ │
│  短期投资                                 ¥0.00 ✎ │  ← 无子科目的一级科目也可编辑
└─────────────────────────────────────────────────┘
```

- ✎ 图标默认隐藏，hover 或获取焦点时显示（移动端始终显示）
- 仅**资产和负债类型**的叶子科目显示编辑图标
- 净资产（权益）类科目不可编辑（余额由系统计算）

### 3.2 点击编辑 — Modal 输入模式

点击余额或 ✎ 图标后，弹出 `<Modal>` 对话框（桌面端和移动端统一交互，遵循设计规范第 10 条）：

```
         ┌──────────────────────────┐
         │                          │
         │  对账 — 存款              │
         │                          │
         │  账面余额      ¥233.00   │
         │  真实余额      [       ]  │
         │  差异          ¥+17.00    │
         │                          │
         │    [取消]    [提交对账]    │
         │                          │
         └──────────────────────────┘
```

- 宽度 `85%`，最大宽度 `420px`，圆角 `14px`，内边距 `24px`
- 遮罩层点击可关闭（等同取消）

**交互细节**：

| 项目 | 说明 |
|------|------|
| 触发方式 | 点击余额数字或 ✎ 图标 |
| 输入框 | 自动聚焦，数字键盘，预填当前余额 |
| 实时差异 | 输入过程中实时计算并显示差异（`输入值 - 账面余额`） |
| 差异颜色 | 差异 > 0 红色（资产增加），差异 < 0 绿色（资产减少），差异 = 0 灰色 |
| 提交 | 调用 `syncService.submitSnapshot(account_id, realBalance)` |
| 取消 | 关闭弹窗，恢复正常显示模式 |
| 键盘快捷键 | Enter 提交，Escape 取消 |

### 3.3 提交后 — 结果反馈

> 用户编辑余额通常是因为发现账面不对，因此**余额不一致（差异 ≠ 0）是主流场景**。

#### 主流程：余额不一致（差异 ≠ 0）

```
┌─────────────────────────────────────────────────┐
│    存款                              ¥250.00  ⚠  │
│                                                 │
│    ⚠ 差异 ¥17.00，已生成调节分录                  │
│    调节分录暂挂至"待分类收入"                      │
│    [前往确认分类 →]                               │
└─────────────────────────────────────────────────┘
```

- 余额立即更新为新值（报表数据重新加载）
- 显示橙色 ⚠ 和差异金额
- 提供"前往确认分类"链接，跳转到 `/sync/reconcile`
- 3 秒后自动恢复正常模式（链接保留在 toast 中）

#### 边界情况：余额一致（差异 = 0）

- 极少出现（用户输入值恰好等于系统余额）
- 仅显示绿色 ✓ toast 提示"余额一致，无需调节"，1.5 秒后自动消失
- 不展开反馈面板，直接恢复正常模式

### 3.4 编辑权限控制

| 科目类型 | 是否可编辑 | 原因 |
|---------|-----------|------|
| 资产 — 叶子科目 | ✅ 可编辑 | 可与外部余额核对（银行、证券等） |
| 资产 — 父科目 | ❌ 不可编辑 | 余额由子科目汇总，不能直接修改 |
| 负债 — 叶子科目 | ✅ 可编辑 | 可与信用卡账单、贷款余额核对 |
| 负债 — 父科目 | ❌ 不可编辑 | 同上 |
| 净资产 — 所有 | ❌ 不可编辑 | 余额由系统计算（资产-负债），不应手动修改 |
| 收入/费用 | N/A | 不在资产负债表中 |

## 4. 数据流

```
用户在资产负债表点击叶子科目余额
        │
        ▼
  进入编辑模式，输入真实余额
        │
        ▼
  点击"提交对账"
        │
        ▼
  前端调用 POST /accounts/{account_id}/snapshot
  body: { external_balance: 250.00 }
        │
        ▼
  后端 create_snapshot() 计算差异
        │
        ├── 差异 < 0.01 → snapshot status = "balanced"
        │                   → 前端提示"余额一致"
        │
        └── 差异 >= 0.01 → 自动生成调节分录
                          → snapshot status = "pending"
                          → 前端提示差异金额 + "前往确认分类"链接
        │
        ▼
  前端重新加载资产负债表数据
  (余额已更新，因为调节分录已入账)
```

## 9. 约束与风险

| 约束/风险 | 说明 | 缓解措施 |
|----------|------|---------|
| 叶子科目判断依赖 `parent_id` | 需根据报表返回的树结构判断节点是否有子节点 | `buildTree` 已构建 `children_map`，直接复用 |
| 资产负债表日期上下文 | 对账提交的是"当前真实余额"，而报表可能选择了历史日期 | 仅当报表日期为今天时显示编辑图标；历史日期下禁用编辑 |
| 对账后余额变化触发等式不平衡 | 调节分录改变单侧余额 | 正常现象，等式校验行会显示"不平衡"提示，用户确认分类后恢复平衡 |
| 频繁对账产生大量调节分录 | 用户可能多次调节同一科目 | 每次对账都是独立的快照记录，调节分录有完整追溯链 |

## 10. 不包含的内容（留待后续）

- 批量对账（一次输入多个科目的真实余额）
- 定期对账提醒（如每月月末提醒对账）
- 对账历史查看（在报表中查看科目的对账记录）
- 资产负债表导出为 PDF/Excel
- 损益表内联编辑（损益类科目不适用余额调节）
- 自动对账（与银行 API 对接自动核对）
